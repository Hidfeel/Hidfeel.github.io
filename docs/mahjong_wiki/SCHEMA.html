⚙️ Schema · LLM Wiki 规范

本 wiki 遵循 Karpathy LLM Wiki pattern

一、三层架构

Raw Sources（原始资料层，只读）：本库 175 篇导出内容（157 公众号文章 + 18 图片），存放于独立导出包，未并入 wiki。

The Wiki（知识层，LLM 生成维护）：本目录下的互链 HTML 页面——摘要页 / 概念页 / 综述页 / 实体页 / 索引页。

The Schema（配置层）：本页定义结构、页面模板与 ingest 工作流。

二、页面类型与本库对应

摘要页 summaries.html：101 篇有效文章的 LLM 要点摘要，每篇含概念交叉引用。
概念页 concepts.html：34 个高频术语的解释与涉及文章。
综述页 analysis.html：4 篇跨文章综合分析。
实体页 entities.html：内容来源「阿发麻将」画像。
索引页 index.html：全局导航与分类目录。

三、Ingest 工作流（本库已执行）

1. 导出 raw（175 篇）→ 2. 筛查有效正文（101 篇，剔除 56 篇微信验证壳）→ 3. 为每篇生成摘要页 + 概念标签 → 4. 聚合概念生成概念页、综合多篇生成综述页 → 5. 更新索引页与日志。

四、Frontmatter 约定

每页顶部以 HTML 注释模拟 YAML frontmatter：title / date / sources / related，便于程序化解析与后续 LLM 维护。

五、质检（Lint）

媒体_id 原样使用；交叉引用双向可达（摘要→概念、概念→摘要）；验证壳不入摘要页，仅在索引页标注"正文受限"。
